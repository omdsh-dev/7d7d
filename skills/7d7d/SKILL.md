# 7d7d 游戏创作

7d7d 是 DSH 的外部游戏门户插件（7k7k 风格）。游戏库在 `~/.dsh/7d7d/games/`（或配置的 root），
**写完文件即上架**——门户每次打开都实时扫描，无需任何注册流程。

## 流程

1. 确定游戏概念：玩法一句话、操作方式（点击/键盘）、目标（得分/通关/无尽）。
2. 在游戏库建目录 `~/.dsh/7d7d/games/<slug>/`，slug 用英文小写短横线（如 `space-shooter`）。
3. 写 `game.json`（见下方 schema）和 `index.html`。
4. 自查质量关卡（见「质量要求」），必要时在浏览器/门户里验证。
5. 告诉用户已上架：`游戏「<title>」已上架 7d7d，点右下角 🎮 即可开玩。`

## game.json schema

```json
{
  "title": "游戏标题",
  "description": "一句话玩法介绍",
  "category": "休闲 | 动作 | 益智 | 射击 | 策略 | 其他",
  "tags": ["标签1", "标签2"],
  "author": "你的署名或 7d7d",
  "type": "html5",
  "emoji": "🎮",
  "createdAt": 1754900000000
}
```

- `type` 为 `"flash"` 时需提供 `game.swf`（只做你自己拥有的 SWF，严禁搬运商业游戏资产）。
- 可选 `cover`（封面图相对路径）、`entry`（html5 入口，缺省 `index.html`）、`swf`（缺省 `game.swf`）。

## 创作约束（html5 游戏）

- **单文件优先**：尽量把 HTML/CSS/JS 全部放进一个 `index.html`；资源多时用相对路径子目录。
- **零外部依赖**：不得引用 CDN 脚本/字体/图片——游戏要在离线沙箱里完整可玩。
- **自包含**：不依赖 localStorage 也能跑（访问需 try/catch 包裹）；键盘事件绑 window；无网络请求。
- **Canvas 为主**：`<canvas>` + requestAnimationFrame 主循环；高分榜可用内存变量 + try/catch 的 localStorage。
- **可玩性**：开局 3 秒内可操作；每局 ≤ 3 分钟；失败要有明显的重开方式（点击/Space/按钮）。
- **UI 完整**：页内显示得分/生命/剩余时间；用 `<div>` 标题栏而非浏览器弹窗。
- **适配门户**：画布宽度建议 480px 内（`width: min(92vw, 480px)`），深色背景与门户协调。
- **体积**：单文件 ≤ 100KB，加载即玩。

## 质量自查清单

- [ ] 首次点击/按键立即有反馈（游戏开始或界面变化）
- [ ] 操作方式在页面上有文字提示
- [ ] 得分/进度可见
- [ ] 失败/通关有明确结束态 + 重开方式
- [ ] 无 console 报错（写完后用 node --check 或浏览器验证）
- [ ] 无外部网络依赖
- [ ] 标题、描述、分类、emoji 都填了

## Flash 游戏（Ruffle）

- Flash 播放前需运行 `pnpm fetch:ruffle`，安装固定版本且经过摘要校验的同源 Ruffle；默认仍优先生成 HTML5 游戏。
- 只接受用户明确提供/授权的 `.swf` 文件。
- 玩法验证受限：Ruffle 兼容 AS1/AS2 成熟、AS3 大部分可用，个别特性有差异，如实告知用户。
- 老 SWF 常见问题：全屏模式失效、右键菜单不同、部分音效缺失。

## 批量创作（游戏节模式）

用户要「一次做 N 款」时：每款游戏用独立子代理/工作流并行产出（各自独立的 slug 目录），
完成后统一汇总上架清单。每款都必须过上面的自查清单，宁缺毋滥。

## 社区投稿

用户想把游戏分享给所有 7d7d 用户时：把游戏目录放进 7d7d 仓库的
`community-games/<slug>/`，运行 `node scripts/update-catalog.mjs` 重新生成
`catalog.json`，提交 PR。合并后全网用户同步即可玩到。投稿同样要过自查清单，
且不得包含任何商业游戏资产（尤其禁止搬运 7k7k/4399 的 SWF）。
